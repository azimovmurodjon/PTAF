## Git Commit Message

```
feat: Soft Assertions, XML/CSV modules, reporting fixes, mobile fixes, and platform improvements

## Summary of Changes

### New Features
- **Soft Assertion Mode** (`soft_assertions.enabled: true` in config.yml)
  - When enabled, failed steps are captured with screenshots and execution continues to the next step
  - At end of scenario, all failures are summarised with timestamps and error messages
  - Failed steps now correctly appear as RED in Extent HTML and PDF reports
  - Works for UI, mobile browser simulation, mobile native app, and native mobile browser
  - @LastScenario features: browser stays open across scenarios even when soft failures occur
  - Normal mode (enabled: false) is completely unchanged

- **XML Automation Module** (new: com.ptaf.xml)
  - Load XML from file or UI element, query by node name or full XPath
  - 15 Cucumber step definitions covering assertions, existence checks, counts, attributes, and variable extraction

- **CSV Automation Module** (new: com.ptaf.csv)
  - Load CSV from file or UI element with configurable delimiter support
  - 14 Cucumber step definitions covering cell assertions, column existence, row counts, and variable extraction

- **Per-Feature Extent Reports** (reporting.per_feature_reports_enabled in config.yml)
  - Generates one individual HTML/PDF report per feature file in addition to the combined report
  - Each report titled with the Feature Name from the feature file declaration

### Bug Fixes
- **UI Automation**: Fixed `IllegalStateException: The page is closed or not initialized` in @LastScenario features — page now returns null instead of throwing, with a clear descriptive error
- **Mobile Native Browser**: Fixed `invalid session id` error for Android Chrome — skips terminateApp/activateApp which was closing the session
- **iOS Safari**: Fixed hanging automation — same terminateApp/activateApp skip applied for iOS Safari
- **Mobile Native App**: Fixed Playwright browser launching unnecessarily during native app scenarios
- **Browser Maximize**: Fixed `maximize_browser: true` not fully maximizing — uses --start-maximized flag correctly without overriding Playwright viewport
- **Mobile Browser Simulation**: Fixed viewport expanding to desktop size — screen size now locked to profile dimensions
- **Maven Build**: Fixed `mvn clean test` running 0 tests — surefire-testng provider now correctly forces TestNG over JUnit Platform auto-detection

### Improvements
- **Mobile element wait**: Two-phase wait (presence then visibility) for more robust native app element detection
- **Mobile session timeout**: newCommandTimeout increased to 300s to prevent premature session closure on slow screens
- **Browser teardown**: TargetClosedError during browser close now logged at DEBUG level instead of ERROR
- **TestNG runner**: com.ptaf.runner.TestRunner now includes com.ptaf.hooks in glue path and correct tags
- **Professional Javadoc**: All 98 Java classes have comprehensive Javadoc and inline comments

### Configuration
All new features are controlled from `config.yml` and default to `false` — zero behavior change unless explicitly enabled:
```yaml
soft_assertions:
  enabled: false        # set true to enable continue-on-failure mode
  retry_seconds: 3      # how long to wait per failed step before moving on

reporting:
  per_feature_reports_enabled: false   # set true for individual feature reports
  per_feature_pdf_enabled: false       # set true to also generate PDFs
```
```

## Microsoft Teams Message

```📢 PTAF Framework Update — July 2026

   Hi team,

   We have a significant update to the PTAF framework. Here is what is new and how to use it.

   ---

   ✅ NEW: Soft Assertion Mode
   When enabled, failed steps no longer stop the test. The framework captures a screenshot, records the failure, and continues to the next step. At the end of the scenario, all failures are summarised. Failed steps appear RED in the report.

   Enable in config.yml:
     soft_assertions:
       enabled: true
       retry_seconds: 3

   Set back to false for normal fail-fast behavior.

   ---

   ✅ NEW: XML Automation — Validate XML files and UI elements containing XML

   How to use:

   Step 1 — Add a sample XML file to your test resources:
     src/test/resources/data/order_response.xml

     <?xml version="1.0"?>
     <order>
       <status>SUCCESS</status>
       <orderId>ORD-12345</orderId>
       <total currency="USD">99.99</total>
       <items>
         <item id="1"><name>Laptop</name><price>99.99</price></item>
       </items>
     </order>

   Step 2 — Write your feature file:

     Feature: Order API XML Validation

       @xml_validation
       Scenario: Verify order response XML
         Given I load XML file "src/test/resources/data/order_response.xml"
         Then XML node "status" equals "SUCCESS"
         Then XML node "orderId" equals "ORD-12345"
         Then XML XPath "//total/@currency" equals "USD"
         Then XML XPath "//items/item" count equals 1
         Then XML node "errorCode" does not exist
         When I extract XML node "orderId" and store as "ORDER_ID"
         Then I log stored variable "ORDER_ID"

   Step 3 — To validate XML content displayed in a UI element:

       Scenario: Verify XML shown in browser text area
         Given we navigate to "https://yourapp.com/api-response"
         Given I load XML from UI element on page "ResponsePage" locator "xmlTextArea"
         Then XML node "status" equals "SUCCESS"
         Then XML XPath "//order/total" equals "99.99"

   Full step reference: src/test/resources/features/xml/xml_automation_example.feature
