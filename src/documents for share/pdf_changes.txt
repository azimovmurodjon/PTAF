Hi Team,

I have completed a framework enhancement for PTAF to support configurable SSL/HTTPS handling and Microsoft SQL Server database connectivity.

The changes include two major updates:

1. Config-controlled SSL/HTTPS bypass for UI and API automation
2. SQL Server DB connection setup using Windows Authentication

For SSL/HTTPS handling, we added a new configuration value in config.yml:

yaml ignoreHTTPSErrors: "true" 

When this value is set to "true", the framework will bypass SSL/HTTPS certificate validation errors. This is useful for QA, DEV, SIT, UAT, and internal environments where certificates may be self-signed, expired, internally issued, or not trusted by the local machine.

When this value is set to "false", the framework will enforce normal certificate validation.

This setting is now applied in both areas:

text UI  -> BrowserFactory applies ignoreHTTPSErrors at BrowserContext level API -> ApiRequestHandler applies ignoreHTTPSErrors at APIRequestContext level 

For the database enhancement, the framework is now set up to support Microsoft SQL Server using Windows Authentication. This means the DB connection does not require username or password when the logged-in user already has database access.

The DB configuration is controlled from config.yml under the database: section:

yaml database:   db_type: "sqlserver"   server_type: "Database Engine"   server_name: "VSDISSQLQA01"   port: "1433"   database_name: "YOUR_DATABASE_NAME"   authentication: "windows"   encrypt: "true"   trust_server_certificate: "true"   login_timeout_seconds: "30"   query_timeout_seconds: "60"   fetch_size: "500"   application_name: "PTAF Automation Framework"   username: ""   password_env_variable: "" 

Before running DB tests, please update:

yaml database_name: "YOUR_DATABASE_NAME" 

with the actual database name from SQL Server Management Studio.

The DB connection flow is now:

text config.yml   -> DatabaseHandler   -> DatabaseConnectionValidator   -> DatabaseSteps   -> DatabaseTestRunner 

A DB health-check scenario was also added so we can validate the DB connection before running full DB validations.

To run the DB health check:

bash mvn test -Dtest=DatabaseTestRunner -Dcucumber.filter.tags="@database_health_check" 

If the DB connection is successful, the scenario should pass and the logs should show SQL Server database product information and JDBC driver details.

If the following error appears:

text This driver is not configured for integrated authentication 

then the framework code is correct, but the local machine may need the Microsoft JDBC native authentication setup for Windows Authentication.

For Maven/Surefire, we are keeping the current plugin version. The only needed update is to make sure the DB runner is included:

xml <include>**/DatabaseTestRunner.java</include> 

Updated/added framework areas include:

text ConfigurationProperties.java ApiRequestHandler.java BrowserFactory.java DatabaseHandler.java DatabaseHooks.java DatabaseActionPerformer.java DatabaseActionImpl.java DatabaseCommonMethods.java DatabaseAction.java DatabaseSteps.java DatabaseTestRunner.java DatabaseConnectionValidator.java database_connection_health_check.feature config.yml pom.xml runner include if needed 

Usage summary:

text For UI/API SSL bypass: - Set ignoreHTTPSErrors: "true" in config.yml  For strict SSL validation: - Set ignoreHTTPSErrors: "false" in config.yml  For SQL Server Windows Authentication: - Set authentication: "windows" - Keep username and password_env_variable empty - Make sure the logged-in Windows user has access to the target DB  For DB health check: - Run DatabaseTestRunner with @database_health_check tag 

This update keeps the framework configuration-driven, avoids hardcoded environment values, and improves enterprise-level maintainability for UI, API, and DB automation.
