# PTAF Mobile Browser Emulation

This folder contains Playwright mobile and tablet browser emulation resources for the existing PTAF UI framework. It is designed for responsive web testing and reuses the same Cucumber feature files, web step definitions, element YAML files, screenshots, videos, and reports already used by PTAF.

## Important Difference

Mobile browser emulation is not native Appium automation. It does not boot a real iOS Simulator or Android Emulator. It uses Playwright browser contexts to simulate mobile/tablet viewport size, screen size, touch capability, device scale factor, and user-agent.

Native mobile app automation remains under:

```text
src/test/resources/mobile
src/main/java/com/ptaf/mobile
```

## Selecting a Mobile Browser Profile

Set the existing `browser` key in `src/test/resources/config/config.yml` to one of the profile names in `config/mobile-browser-profiles.yml`.

```yaml
browser: "iPhone 17 Pro Max Safari"
```

or:

```yaml
browser: "Galaxy S25 Ultra Chrome"
```

## Execution Controls

Runtime behavior is controlled from:

```text
src/test/resources/mobile_browser/config/mobile-browser-execution.yml
```

| Config Key | Purpose |
|---|---|
| `mobile_browser.orientation` | `profile`, `portrait`, or `landscape`. Use `profile` to keep each profile's default orientation. |
| `mobile_browser.evidence.screenshot_on_failure` | Capture screenshots only when a scenario fails. |
| `mobile_browser.evidence.screenshot_on_pass` | Capture screenshots for passed scenarios. |
| `mobile_browser.evidence.screenshot_after_each_scenario` | Capture screenshots for every scenario. |
| `mobile_browser.evidence.attach_screenshots_to_report` | Attach screenshots to Cucumber/Extent reports. |
| `mobile_browser.evidence.video_recording_enabled` | Enable Playwright video recording for mobile browser profiles. |
| `mobile_browser.evidence.video_size_width` | Width of recorded mobile browser video. |
| `mobile_browser.evidence.video_size_height` | Height of recorded mobile browser video. |

## Portrait and Landscape

To force all selected mobile browser profiles into portrait mode:

```yaml
mobile_browser:
  orientation: "portrait"
```

To force landscape mode:

```yaml
mobile_browser:
  orientation: "landscape"
```

To keep each profile's own default orientation:

```yaml
mobile_browser:
  orientation: "profile"
```

## Evidence Output

Screenshots and videos are written under:

```text
test-output/mobile-browser-evidence/<run-id>/
```

Videos are generated by Playwright when the browser context is closed. Keep video disabled by default for daily execution because large suites can generate many large files.

## Enterprise Team Guidance

For large teams, testers should update YAML profile/config files instead of changing Java code. Add new devices by copying an existing profile in `mobile-browser-profiles.yml`, changing the viewport/screen/user-agent values, and using the new profile name in `config.yml`.

## Visual Regression Testing

Mobile browser visual testing is now built into the Playwright mobile-browser layer. It captures the current page screenshot, compares it against a profile-specific baseline image, writes the actual and diff artifacts, and attaches baseline/actual/diff images to the Cucumber/Extent report when configured.

| Visual Config Key | Purpose |
|---|---|
| `mobile_browser.visual.enabled` | Turns visual testing on or off. |
| `mobile_browser.visual.baseline_directory` | Stores expected baseline images by browser profile. |
| `mobile_browser.visual.output_directory` | Stores actual and diff images from test execution. |
| `mobile_browser.visual.mismatch_threshold_percent` | Maximum allowed visual difference percentage. |
| `mobile_browser.visual.create_baseline_if_missing` | Creates a baseline automatically on first run if missing. |
| `mobile_browser.visual.attach_artifacts_to_report` | Attaches baseline, actual, and diff images to reports. |

Example Cucumber step:

```gherkin
Then I compare mobile browser page with visual baseline "home-page"
```

Baseline files are organized by browser profile. For example, if the selected browser is `Galaxy S25 Ultra Chrome`, the baseline path is:

```text
src/test/resources/baselines/mobile_browser/Galaxy_S25_Ultra_Chrome/home-page.png
```

On comparison, actual and diff files are created under:

```text
test-output/mobile-browser-visual/<run-id>/Galaxy_S25_Ultra_Chrome/
```

For enterprise use, keep `create_baseline_if_missing: true` only while building baselines. In CI, set it to `false` so missing baselines fail the build instead of silently creating new expected images.
